# Chronos 前端设计阶段规划

## 当前目标

先把 Chronos 的 Web 前端体验做完整，围绕日历、闹钟、任务、设置和 Chat 覆盖层建立稳定的视觉与交互基础。当前阶段以浏览器本地预览为主，优先验证信息架构、页面状态和关键操作路径。

## 工作范围

### 1. 视觉基础

- 统一字体、颜色、间距、圆角、阴影和图标使用规则。
- 建立浅色/深色主题下的可读性和状态色规范。
- 约束桌面端与移动端的响应式断点，确保核心内容不遮挡、不溢出。

### 2. 核心页面

- 日历主界面：日期切换、时间轴、事件详情和空状态。
- 闹钟页面：列表、启用/停用、编辑、新建和无数据状态。
- 任务与设置页面：导航、表单、开关、反馈和错误状态。
- Chat 覆盖层：打开/关闭、连接中、对话中、断开和失败状态。

### 3. 交互与组件

- 优先完善导航、弹层、表单、切换、筛选和反馈提示等高频组件。
- 所有按钮、图标按钮和输入控件补齐 hover、focus、pressed、disabled、loading 状态。
- 使用前端 fallback 数据支持无后端预览，便于快速迭代和验收。

### 4. 验收方式

- 以 Expo Web 为主要运行入口，在桌面和窄屏视口检查布局。
- 覆盖首次进入、空数据、加载中、操作成功和操作失败等状态。
- 每次迭代优先保留可直接打开的前端预览，不把后端服务作为设计验收前置条件。

## 实施顺序

1. 梳理现有页面和组件，确定信息架构与视觉 tokens。
2. 完成日历主界面及其响应式布局。
3. 完成闹钟、任务、设置页面的主要交互状态。
4. 完善 Chat 覆盖层和跨页面导航体验。
5. 做桌面/移动视口验收，集中修复溢出、遮挡和状态缺失问题。

## 暂不纳入本阶段

- 用户登录、远程数据持久化和账号状态。
- 语音服务、实时房间和原生闹钟调度。
- 容器化、本地数据库和部署环境搭建。

这些能力保留现有代码接口，待前端体验稳定后再单独排期接入。
